# `forms` package

This package contains the static data that encodes each tax form supported by the app, as well as the static glossary content.
The static information about each tax form is referred to as a "form specification."

Each supported tax year (`TAX_YEARS` in `@thumbtax/common`) has its own full set of form specifications, called a "specification registry."
Years don't fall back to each other.
The glossary is shared across all years.

## Modules

- `forms/src/`
  - `build/`: Additional code for the `buildForms` script
  - `data/`: Static Markdoc files that encode each year's form specifications and the glossary
  - `generated/`: TypeScript files generated by the `buildForms` script, including each year's specification registry
  - `schema/`: Additional code for the Markdoc schema
  - `types/`: Tax form type definitions
  - `buildForms.ts`: Code-generation script that maps `data/` to `generated/`
  - `index.ts`: Exports the specification registry of each tax year (`specificationsByYear`) and the glossary
  - `schema.ts`: Defines the Markdoc schema and validation

## Scripts

- `npm run build:meta`: Compile the Markdoc schema and `buildForms` script
- `npm run build:forms`: Run the compiled `buildForms` script
  - Builds everything by default.
    To build specific files, pass paths relative to `data/`, such as `npm run build:forms -- 2025/f1040.mdoc glossary/glossary.mdoc`.

## Adding a tax year

1. Add the year to `TAX_YEARS` in `@thumbtax/common`.
2. Copy the latest `data/{year}/` folder, including partials, and rename the year prefix in its partial references (`{% partial file="{year}/..." /%}`).
3. Add the new partial imports to `schema.ts`.
4. Run the forms build to generate `generated/{year}/`.
5. Add the generated registry to `specificationsByYear` in `index.ts`.
6. Update the new year's specifications.
   If a form was added or removed, write a placeholder specification for the years that don't have it.
